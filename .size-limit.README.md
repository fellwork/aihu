# `.size-limit.json` policy

This document is the authoritative reference for which scribe packages carry a `.size-limit.json` row and which do not. The policy is enforced by `scripts/check-size-rows.ts`, wired as the `bun run check:size-rows` script.

## Why a policy exists

scribe's contract is "browser bundle ≤ 3.46 kB gz". That budget only applies to packages whose code is actually loaded into a browser bundle. Other packages — SSR-side runtimes, build-time plugins, the compiler — have legitimate footprints orders of magnitude larger and are budgeted via different mechanisms (SSR-bytes-served, dep-tree audit, install-size budgets). Mixing them into `.size-limit.json` would either pollute the browser-bundle gate with irrelevant noise or force artificial sub-kilobyte limits on code that has no business being there.

## Three classifications

Every workspace package under `packages/*` falls into exactly one bucket.

### Browser-eligible — MUST have a `.size-limit.json` row

These packages export browser-runtime code that lowers into a `dist/index.js` consumed by `@scribe/runtime` or end-user `*.scribe` SFCs. They count against the 3.46 kB ceiling.

| Package | Current limit |
|---|---|
| `@scribe/signals` | 1970 B |
| `@scribe/arbor` | 2200 B |
| `@scribe/runtime` | 1170 B |
| `@scribe/data` | 750 B |
| `@scribe/router` | 1536 B |
| `@scribe/context` | 300 B |
| `@scribe/agent` | 200 B |
| `@scribe/agent-service` | 600 B |

Adding a new browser-eligible package is the trigger for a new row. The CI lint will fail the build if a package adds `src/index.ts` and is not classified server-side or build/dev-time-only.

### Server-side — MUST NOT have a row

These packages run on a Node/Bun server and are budgeted by SSR-bytes-served plus a dep-tree audit. They never ship to a browser bundle.

- `@scribe/server` — SSR runtime (`engines.node` requirement)
- `@scribe/agent-readiness` — content-negotiation + llms.txt helpers (depends on `@scribe/server`)

If you find yourself wanting to import these from browser code, that's the bug — fix the dependency direction, do not add a row.

### Build/dev-time-only — MUST NOT have a row

These packages run in the build toolchain or dev tooling. They never reach a browser bundle.

- `@scribe/plugin` — plugin API helpers consumed by user `vite.config.*` etc.
- `@scribe/compiler` — Rust-backed `.scribe` SFC compiler with a thin JS wrapper

## Adding or removing a row

When adding a browser-eligible package:

1. Add the row to `.size-limit.json` with a conservative limit (round up from current `bun run size` output by ~10 %).
2. Update the table above.
3. `bun run check:size-rows` should remain green.

When promoting a server-side or build/dev-time package to browser-eligible (rare; treat as a v-bump):

1. Update the classification allowlist in `scripts/check-size-rows.ts`.
2. Add the row to `.size-limit.json`.
3. Update this README and `bench/signals/HARNESS.md` § "Size budgets".
