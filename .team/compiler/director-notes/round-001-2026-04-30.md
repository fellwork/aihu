**OQ-C9 adjudication — Which emit pattern?**

**Option A** — `defineElement('x-counter', defineComponent(setup_fn))`.

Rationale: Option A reuses `defineComponent`, which is already tested, already handles shadow root attachment (via `defineElement`'s wrapper), and already wires `connectedCallback`/`disconnectedCallback` correctly through the class it returns. Option B (full class) requires the compiler to emit correct `connectedCallback`, `disconnectedCallback`, and `#scope` field management — non-trivial generated code that has never been tested. In v0, generating untested boilerplate is a quality risk. The `define-element.ts` comment describes Option B as a *future compiler target*, not a v0 requirement.

Canonical v0 emit form: `defineElement('x-counter', defineComponent(ctx => { ...; return branch(...) }))`

**OQ-C10 adjudication — `leaf()` Signal<string> type cast:**

Emit `as unknown as Signal<string>` cast in v0. The runtime discriminates signals by `Array.isArray(value)`, not by the type parameter. The cast is a TypeScript-layer workaround only — explicit, auditable, and easy to remove in v1 when `leaf()` is widened to `Signal<unknown>`. Architect must specify the exact cast form.

**OQ-C11 adjudication — Rust toolchain version pin:**

Pin `rust = "1.87.0"` in `.prototools`. Also create `rust-toolchain.toml` at repo root with `channel = "1.87.0"` for tools that read it directly (cargo, rust-analyzer).

```rust
pub struct ScribeSource<'a> {

}

```

**Canonical compiler emit output for `counter.scribe` (Phase C-3 snapshot target):**

```typescript
import { branch, leaf } from '@scribe/arbor'
import type { Signal } from '@scribe/signals'
import { signal } from '@scribe/signals'
import { defineComponent, defineElement } from '@scribe/runtime'

defineElement('counter', defineComponent((_ctx) => {
  const [count, setCount] = signal(0)
  const increment = () => setCount(c => c + 1)

  return branch('div', { class: 'counter' }, [
    branch('span', null, [leaf([count, setCount] as unknown as Signal<string>)]),
    branch('button', { onclick: increment }, [leaf('+')])
  ])
}))
```

Key decisions encoded:
- Tag name `'counter'` derived from filename `counter.scribe`.
- `defineElement` + `defineComponent` two-call pattern (Option A).
- `as unknown as Signal<string>` cast on signal tuples passed to `leaf()`.
- Event handler as `{ onclick: fn }`.
- No `export default` — `defineElement` is a registration side-effect.
- `Signal` type imported separately for the cast; `signal` value import separate.

**CLI interface:**

```
scribe-compile <file.scribe> [--out <dir>] [--tag <name>]
```

Stdout by default; `--out <dir>` writes `<filename>.ts`; exit code 1 on compile error with `file:line: message` on stderr.
