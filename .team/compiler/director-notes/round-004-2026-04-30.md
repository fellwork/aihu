### Q2 — Public function signature

```rust
pub fn emit(unit: &CompileUnit, tag_name: &str) -> String
```

- Takes `&CompileUnit` (not consumed — C-3 does not need ownership).
- Takes `tag_name: &str` as a separate parameter. The caller (e.g., CLI or `compile_full` pipeline) is responsible for deriving the tag name from the filename stem or `unit.source.meta.name`. `emit()` does not do filesystem operations.
- Returns `String` — infallible. In v0 all error conditions that would cause a codegen failure (undefined identifiers, unsupported node types) are already ruled out by the template parser's strict constraints. If `template_ast` is `None`, `emit()` returns a valid TypeScript file with an empty `branch` body (see Q6 below).

Do NOT add a `tag_name_from_unit()` helper inside `emit.rs`. Keep tag name derivation logic in `lib.rs` or the caller.

### Q3 — Import block algorithm

The import block is always 4 lines, in this fixed order:

```typescript
import { branch, leaf } from '@aihu/arbor'
import type { Signal } from '@aihu/signals'
import { signal } from '@aihu/signals'
import { defineComponent, defineElement } from '@aihu/runtime'
```

**Omit rule for `import type { Signal }`:** Omit this line if and only if `unit`'s `SignalMap` is empty (i.e., `resolve_signals(script)` returns a map with zero entries). When no signals exist, `leaf()` is never called with a signal tuple, so the `Signal` type is unreferenced.

**Omit rule for `import { signal }`:** Omit this line if and only if the raw script block contains no `signal(` call. In v0 this is approximated by checking whether `resolve_signals()` returns a non-empty map — a non-empty `SignalMap` implies `signal` was imported. If the map is empty, the `import { signal }` line is also omitted.

Concretely: if `signal_map.0.is_empty()`, emit only 2 import lines (arbor, runtime). If non-empty, emit all 4. The `@aihu/arbor` and `@aihu/runtime` imports are always present.

The Architect must encode this as an explicit `if signal_map.0.is_empty()` branch in the spec — not a loop over a dynamic list. Import ordering is static and must never vary.

### Q4 — `defineElement` wrapper

The emitted file structure is:

```typescript
<import block>

defineElement('<tag_name>', defineComponent((_ctx) => {
  <script body>

  return <template tree>
}))
```

`tag_name` is passed in directly as the `tag_name: &str` parameter. Emit it as a string literal without further processing inside `emit()`.

The v0 hyphen warning (architecture.md Section 7 locked decisions) must be emitted to `eprintln!` inside `emit()` when `!tag_name.contains('-')`. This is the only stderr output from `emit()`. It does not affect the returned `String`.

**`_ctx` parameter:** Always present. Never `ctx`. No conditional logic. Every generated `defineComponent` call uses `(_ctx)`.

### Q5 — Script passthrough

The `<script setup>` body must be emitted verbatim after stripping import lines.

Algorithm:
1. Take `unit.source.script.unwrap_or("")`.
2. Split into lines.
3. Filter out any line whose `trim()` starts with `import ` or `import\t` (i.e., any import statement). This includes `import { signal }`, `import type { ... }`, `import * as ...`, etc. — all are stripped since the import block is reconstructed by the emit logic.
4. Collect remaining lines, preserving relative order and internal whitespace. Strip only leading blank lines and trailing blank lines from the collected result (apply `trim_start_matches('\n')` equivalent on the joined block, then `trim_end_matches('\n')` equivalent).
5. The resulting text is the script body, emitted between the `defineComponent((_ctx) => {` opening and the `return` statement.
6. A blank line separates the script body from the `return` statement.

If the script body (after import stripping) is empty, emit no blank line between the opening `(_ctx) => {` and `return`.

### Q6 — Template walk algorithm

The template walk produces a `String` representing a single Rust-to-TypeScript `branch()`/`leaf()` expression tree. It is a recursive function with this private signature inside `emit.rs`:

```rust
fn emit_node(node: &TemplateNode, signal_map: &SignalMap) -> String
```

And a top-level dispatcher:

```rust
fn emit_nodes(nodes: &[TemplateNode], signal_map: &SignalMap) -> String
```

**`emit_nodes` rules:**
- 0 nodes: return `"branch(null, null, [])"` — this is the empty-body case when `template_ast` is `None` or an empty vec.
- 1 node: return `emit_node(node, signal_map)` directly (no wrapping branch).
- 2+ nodes at the same level: return `"branch(null, null, [<comma-separated emit_node results>])"` — root fragment wrapping per the locked design decision.

**`emit_node` rules:**

- `TemplateNode::Element { tag, attrs, children }`:
  - Attrs string: `emit_attrs(attrs)` — see Q8.
  - Children string: if `children.is_empty()`, use `"[]"`. Otherwise `"[<comma-separated emit_node results for each child>]"`.
  - Emit: `branch('<tag>', <attrs_string>, <children_string>)`.
  - If attrs is empty and children is empty: `branch('<tag>', null, [])`.
  - If attrs is non-empty: `branch('<tag>', { <attr entries> }, [<children>])`.

- `TemplateNode::Text(s)`:
  - Emit: `leaf('<s>')` — single-quoted string literal.
  - Trim `s` before emitting. If trimmed `s` is empty, skip this node (do not emit).

- `TemplateNode::Interpolation(identifier)`:
  - Consult `signal_map.0.get(identifier)`:
    - **Found** (read name maps to write name): emit `leaf([<read>, <write>] as unknown as Signal<string>)`.
    - **Not found**: emit `leaf(<identifier>)` — no cast, bare identifier reference.

Indentation: the Architect must specify exact indentation. The top-level `return` statement is indented 2 spaces (inside `defineComponent`). Each level of nesting in the `branch()`/`leaf()` tree adds 2 additional spaces. Use a `depth: usize` parameter on `emit_node` and `emit_nodes` for indentation tracking. The counter fixture output in Section 7 is the oracle — the Architect must verify that the indentation algorithm produces that exact output.

### Q7 — Signal vs plain interpolation (already embedded in Q6)

The `SignalMap` lookup is the sole discriminator:
- `signal_map.0.contains_key(identifier)` → signal form with cast.
- Otherwise → plain form, no cast.

No other heuristic (naming convention check, `set`-prefix check, etc.) is used. The map is authoritative.

### Q8 — `@attr` → `onclick` mapping in AttrMap object literal

`emit_attrs(attrs: &[Attr]) -> String` produces the second argument to `branch()`.

- Empty `attrs` vec → `null` (not `{}`).
- Non-empty: `{ <key>: <value>, <key>: <value>, ... }` inline object literal. No trailing comma after last entry.

Per-variant rules:
- `Attr::Static { name, value }` → `<name>: '<value>'` (single-quoted string literal for value).
- `Attr::Binding { name, expr }` → `<name>: <expr>` (bare identifier, no quotes).
- `Attr::Event { name, handler }` → `on<name>: <handler>` — prepend `on` to the event name. `@click` parses to `Attr::Event { name: "click", handler: "increment" }`, which emits as `onclick: increment`.

The `on`-prefix rule applies unconditionally to all `Attr::Event` variants. There is no allowlist or special-casing for specific event names.

### Q10 — `compile_full()` integration: does `emit()` call `resolve_signals()` internally?

**Decision: `emit()` calls `resolve_signals()` internally.**

`emit()` signature remains `pub fn emit(unit: &CompileUnit, tag_name: &str) -> String`. Inside `emit()`, the first line of implementation is:

```rust
let signal_map = resolve_signals(unit.source.script.unwrap_or(""));
```

Rationale: callers should not need to call `resolve_signals()` separately before calling `emit()`. `CompileUnit` already carries `source.script`. Keeping `emit()` self-contained means the public API for C-3 is exactly one function. The `SignalMap` remains a public type (needed for testing `resolve_signals()` in isolation), but it is an implementation detail of `emit()`'s internal pipeline.

The Architect must reflect this in the `emit()` function skeleton in Section 16 and must NOT add a `signal_map: &SignalMap` parameter to the public signature.

## Open questions / risks

**Risk R1 — Indentation oracle sensitivity.** The Section 7 emit target uses 2-space indentation. The Architect must walk the counter fixture manually and verify the depth-tracking algorithm produces the exact whitespace. A 2-vs-4 space discrepancy will cause C3-1 to fail snapshot assertion. The Architect should include a worked trace of the counter fixture in Section 16.

**Risk R2 — `Text` node whitespace in mixed content.** Architecture Section 12.3 states that `Text` nodes preserve internal whitespace and appear as siblings of `Interpolation` nodes. In the counter fixture there are no mixed-content nodes (only pure interpolation or pure text children). The test inventory includes test 2 (no signals) which exercises `leaf(message)` from an interpolation, but no test exercises a `Text` + `Interpolation` sibling pair. The Architect should include a dedicated test or at minimum document that the `Text("")` trim-and-skip rule handles this correctly. This is not a blocker for C3-1 but will surface in C-4.

**Risk R3 — `<style>` block in `CompileUnit`.** `unit.source.style` may be `Some(...)`. The `emit()` function must explicitly ignore it. The Architect must document a guard: `if unit.source.style.is_some() { eprintln!("warning: <style> block ignored in v0 output"); }`. This is the C3-7 behavior.

**Risk R4 — Build manifest retirement.** The retro notes that no build manifest was produced for C-2 and asks whether to retire the format. Decision: retired. The verification report is sufficient. Do not produce a `build-manifest-c3.md`. The Verifier should confirm via the 11 criteria in Section 8 and the `counter.aihu.snap` snapshot.

**Risk R5 — `bun tsc --noEmit` validation (C3-2).** The emitted TypeScript must typecheck against `@aihu/arbor`, `@aihu/signals`, and `@aihu/runtime`. These packages exist in the repo. The Verifier must confirm a `tsconfig.json` accessible to the test is available, or document how C3-2 is satisfied. This is a Verifier responsibility, not a Builder responsibility, but the Architect should note it in Section 16 so the Builder writes the snapshot correctly.

**No open questions** — all design decisions from the brief are resolved above.
