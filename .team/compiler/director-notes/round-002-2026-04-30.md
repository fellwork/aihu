### Item C: Template parser algorithm depth

**Decision: Architect specifies strategy, tokenization, text/interpolation splitting, identifier extraction — not the implementation.**

The Architect must specify:

1. **Parsing strategy:** Recursive descent. Hand-rolled. No third-party HTML parser crate. No event-driven SAX-style parsing.
2. **Tokenization:** No separate token stream. The parser maintains a `pos: usize` cursor into the `&str` input, scanning for character boundaries directly — consistent with `sfc.rs` approach.
3. **Text/interpolation splitting:** Within content between element tags, split on `{{` / `}}` boundaries. Characters before first `{{` → `Text` node. `{{ identifier }}` span (optional whitespace inside) → `Interpolation` node. Characters after `}}` before next `<` or `{{` → another `Text` node. Multiple `Text` and `Interpolation` nodes may be siblings.
4. **Identifier validation:** Strip `{{` / `}}`, `str::trim()` interior. If result contains whitespace or doesn't match `[a-zA-Z_][a-zA-Z0-9_]*` → `Err(CompileError)` with message: `"interpolation must be a single identifier in v0; expressions are not supported"`.
5. **Attribute prefix discrimination:** `@` → `Attr::Event` (strip `@`, split on `=`). `:` → `Attr::Binding` (strip `:`, split on `=`). `v-if` / `v-for` → `Err` with message: `"v-if / v-for directives are not supported in v0; see v1 roadmap"`. Any other `v-` → `Err` with message: `"unknown directive '{name}'; scribe v0 supports @event, :attr, and {{ identifier }} only"`. All others → `Attr::Static`.
6. **Self-closing tags:** Not supported in v0 → `Err(CompileError)` with message: `"self-closing tags are not supported in v0 template parser"`.
7. **Top-level text:** A template whose content begins with non-tag characters yields a `Text` node as a top-level sibling — not an error.

Architect must NOT specify cursor struct fields, function names, match arm structure, or other implementation detail.

## 4. Scope signal

**Continue Phase C-1. No change to approach.**

Critical finding: `TemplateNode` fields must use owned `String`, not `&'a str` slices.

`ScribeSource<'a>` returns `template: Option<&'a str>`. The template parser receives this `&str` and must produce a `TemplateNode` tree. The tree cannot carry `'a` lifetime slices because:
- Text nodes and interpolation identifiers are produced by stripping delimiters — not contiguous substrings of the source.
- Carrying `'a` lifetimes into `TemplateNode` would bind the AST lifetime to the source string and complicate the C-2/C-3 pipeline.
- `insta` snapshot debug output is cleaner with owned `String`.

Correct function signature: `pub fn parse_template(input: &str) -> Result<Vec<TemplateNode>, CompileError>` where `TemplateNode` owns all its string data.
