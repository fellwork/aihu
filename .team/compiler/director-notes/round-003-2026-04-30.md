## 2. Q1 adjudication — `parse_template()` wiring

**Decision: Two-function API. `compile()` unchanged. New `compile_full()` function. Zero snapshot churn.**

Rationale: Adding `parsed_template` to `ScribeSource` forces re-acceptance of all 5 sfc_split snapshots for the third time in two sessions, creates redundancy between `source.template` (raw slice) and the parsed AST, and introduces a correctness risk if they diverge. A standalone helper function defers the pipeline problem to C-3. The clean solution is a second public entry point that callers of the pipeline (C-3, final CLI) use, while existing tests remain unchanged.

### New type: `CompileUnit<'a>` in `src/types.rs`

```rust
#[derive(Debug)]
pub struct CompileUnit<'a> {
    pub source:       ScribeSource<'a>,
    pub template_ast: Option<Vec<TemplateNode>>,
}
```

`TemplateNode` uses owned `String` (established C-1). `CompileUnit` derives `Debug` only — not `PartialEq`. Snapshot assertions cover it.

### New function: `compile_full()` in `lib.rs`

```rust
pub fn compile_full(source: &str) -> Result<CompileUnit<'_>, CompileError> {
    let sfc = parser::sfc::parse(source)?;
    let template_ast = match sfc.template {
        Some(tmpl) => Some(parser::template::parse_template(tmpl)?),
        None => None,
    };
    Ok(CompileUnit { source: sfc, template_ast })
}
```

**`ScribeSource` in C-2: NO CHANGES.** Frozen. `compile()` signature unchanged. All 5 sfc_split snapshots and the `compile_empty_source` assertion test remain unmodified.

## 3. Q2 adjudication — `SignalMap` type and `src/codegen/` structure

### `SignalMap` concrete type

```rust
use std::collections::HashMap;

#[derive(Debug, Default, PartialEq)]
pub struct SignalMap(pub HashMap<String, String>);
```

Newtype wrapper over `HashMap<String, String>`. Not a type alias — a type alias cannot have methods and is harder to extend. `Default` gives `SignalMap::default()` as empty-map constructor. Inner field `pub` allows direct access in tests (`map.0.get("count")`).

### `resolve_signals()` function signature

```rust
pub fn resolve_signals(script: &str) -> SignalMap
```

- Takes raw `&str` (script block text).
- Returns `SignalMap` — **non-fallible**. Non-matching lines are silently skipped. There is no malformed-signal error in v0. C-3 will fail at codegen if a template references an identifier not in the `SignalMap` — that is a C-3 error, not C-2.
- Algorithm: iterate lines; for each line, `str::trim()`; if trimmed line starts with `const [` AND contains `] = signal(`: extract identifiers between `[` and `]`, split on `,`, trim each; insert read→write pair. Skip line silently if pattern not matched or identifiers empty after trim.
- **No regex crate.** String scanning only — consistent with the hand-rolled parser decision locked in C-1.
