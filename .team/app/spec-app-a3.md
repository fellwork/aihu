**Date:** 2026-05-04
**Scope:** V0 — SPA output mode only
**Input specs:** A1 (ScribeConfig), A4 (route param protocol), Scout S1-S3

## 1. `createApp()` TypeScript Signature

```typescript
// packages/app/src/client.ts
export function createApp(): void
```

**V0 is zero-argument.** All runtime config is read from the `virtual:scribe-config` virtual module injected by the Vite plugin. No inline config parameter — convention-first for V0; V1 can add optional overrides if friction proves the convention insufficient.

Future V1 signature (do NOT implement now):
```typescript
export function createApp(overrides?: Partial<ScribeAppConfig>): AppInstance
```

## 2. `virtual:scribe-config` Virtual Module Shape

The `viteAppPlugin()` Vite plugin resolves `virtual:scribe-config` at build/dev time. The null-prefixed internal ID is `\0virtual:scribe-config` — matching the `RR`/`LR` convention in `packages/router/src/vite-plugin.ts` lines 19-20.

**Generated module:**
```typescript
// AUTO-GENERATED by @scribe/app viteAppPlugin — do not import directly
export interface ScribeAppConfig {
  outletId: string    // default: 'outlet'
  title?: string      // from scribe.config.ts app.head.title
  base?: string       // default: '/'
}

const config: ScribeAppConfig = {
  outletId: 'outlet',
  title: 'My Blog',
  base: '/',
}
export default config
```

The `load()` hook serializes `ScribeAppConfig` fields as a JSON literal embedded in `export default { ... }` — the same pattern as `genR()` in `packages/router/src/vite-plugin.ts` line 110.

**TypeScript ambient declaration** (needed for TypeScript users):
```typescript
// packages/app/src/virtual.d.ts
declare module 'virtual:scribe-config' {
  import type { ScribeAppConfig } from '@scribe/app'
  const config: ScribeAppConfig
  export default config
}
```

**SSR safety:** `virtual:scribe-config` exports only plain data — no DOM references. Safe to import in any context. `createApp()` itself (which calls `document.getElementById`) lives in `@scribe/app/client` only.

## 3. Module Export Structure

### `@scribe/app` (main entry — `src/index.ts`)

Build/dev-time and config-authoring surface. SSR-safe — never imports DOM APIs.

Exports:
- `defineConfig(config: ScribeAppConfig): ScribeAppConfig` — typed identity function
- `type ScribeAppConfig` — user-facing config shape
- `viteAppPlugin()` — Vite plugin factory for `virtual:scribe-config` resolution

Does NOT export `createApp` — prevents accidental browser code in Vite configs.

### `@scribe/app/client` (client entry — `src/client.ts`)

Browser-only runtime bootstrap. The path users import in `src/main.ts`.

Exports:
- `createApp(): void`

Imports at runtime: `@scribe/router`, `@scribe/arbor`, `@scribe/signals`, `@scribe/runtime`, `virtual:scribe-routes`, `virtual:scribe-config`.

### `package.json` exports map

```json
{
  "name": "@scribe/app",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js"
    },
    "./client": {
      "types": "./dist/client.d.ts",
      "import": "./dist/client.js"
    }
  }
}
```

### Size policy

`@scribe/app/client` ships to the browser. Add `.size-limit.json` row:
```json
{ "name": "@scribe/app", "path": "packages/app/dist/client.js", "limit": "400 B", "gzip": true,
  "ignore": ["@scribe/router", "@scribe/arbor", "@scribe/signals", "@scribe/runtime"] }
```

The 400 B budget covers only the bootstrap logic (outlet lookup, render loop, click interceptor, popstate). Peer deps are already budgeted in their own rows and are excluded by `ignore`.

## 4. Outlet Convention

`id="outlet"` is the hard V0 convention.

`createApp()` reads `config.outletId ?? 'outlet'` from `virtual:scribe-config`. In V0, `outletId` is always `'outlet'` (the config type reserves the field for V1 configurability without a breaking type change). The CLI scaffolder's `appIndexHtml()` already emits `<div id="outlet"></div>`.

If the outlet element is not found:
```typescript
throw new Error(
  '@scribe/app: no element with id="outlet" found. Add <div id="outlet"></div> to your index.html'
)
```

Never silently no-op — this is always a developer error.

## 5. `_setMount`/`_setSignal` Ownership

**V0: `createApp()` calls `_setMount(mount)` and `_setSignal(signal)` once at startup. `_injectAutoWiring` in the compiler plugin stays in place as an idempotent fallback.**

```typescript
// createApp() preamble:
import { mount } from '@scribe/arbor'
import { signal } from '@scribe/signals'
import { _setMount, _setSignal } from '@scribe/runtime'

_setMount(mount)
_setSignal(signal)
```

The `_setMount`/`_setSignal` calls are idempotent — `packages/runtime/src/define-component.ts` has a null-guard at lines 7 and 33. Double-calling has zero runtime cost.

**V1 optimization (deferred):** When `createApp()` is confirmed stable, remove `_injectAutoWiring` from the compiler plugin for modules loaded through `createApp()`. Signal via a build-time define `__SCRIBE_APP__: true` set by `scribe()` Vite plugin.

## 6. 404 Handling

**V0: inline fallback + `404.scribe` convention check (wildcard route scan).**

Priority in `render(match)`:
1. `router.match(pathname)` returns a match → render normally
2. No match → scan `routes` array (from `virtual:scribe-routes`) for entry where `route.pattern === '*'` or `route.name === 'not-found'` → render that route (the `404.scribe` convention)
3. No wildcard/not-found route → render inline fallback:
   ```typescript
   const p = document.createElement('p')
   p.style.cssText = 'font-family:system-ui;padding:2rem;color:#888'
   p.textContent = '404 — page not found'
   outlet.replaceChildren(p)
   ```

The inline fallback copies verbatim from `examples/blog-router/src/main.ts` lines 9-14.

### `src/main.ts` — replaces the 44-line bootstrap

```typescript
import { createApp } from '@scribe/app/client'
createApp()
```

**Two lines. That is the complete file.**

### `scribe.config.ts` — new optional file

```typescript

export default defineConfig({

      title: 'My Blog',
    },
  },

```

If absent, all defaults apply — `outletId: 'outlet'`, no title.

### `vite.config.ts` — before / after

**Before (current blog-router):**
```typescript

export default {
  plugins: [scribeCompilerPlugin(), viteRouterPlugin({ pagesDir: 'src/pages' })],
}
```

**After (V0 with @scribe/app — two options):**

Option A (using composed `scribe()` from A2):
```typescript
import { defineConfig } from 'vite'
import { scribe } from '@scribe/app'
export default defineConfig({ plugins: [scribe()] })
```

Option B (incremental — add only `viteAppPlugin` if not adopting full composition yet):
```typescript
import { viteRouterPlugin } from '@scribe/router/plugin'
import { scribeCompilerPlugin } from '@scribe/compiler'
import { viteAppPlugin } from '@scribe/app'

export default {
  plugins: [scribeCompilerPlugin(), viteRouterPlugin({ pagesDir: 'src/pages' }), viteAppPlugin()],
}
```

## 10. Builder Risks

1. **`virtual:scribe-routes` declaration location** — `client.ts` imports it; confirm existing declaration file pattern before authoring `virtual.d.ts` for `virtual:scribe-config`
2. **`scribe.config.ts` loading** — For V0, use regex extraction (matching `readScribeRouteName` pattern in router plugin) rather than `loadConfigFromFile`; fall back to defaults if file absent
3. **A4 coordination** — `createApp()` implements flat per-attribute `setAttribute` (new protocol); if A4 isn't landed first, use the old JSON `route` attribute temporarily. The two protocols are the only breaking change between old `main.ts` and new `createApp()`.
4. **Size row path** — Row `name` must be `@scribe/app`; `path` points to `dist/client.js` not `dist/index.js`
5. **`_injectAutoWiring` double-call** — Idempotent in V0; do not remove from compiler plugin until `createApp()` is proven stable
