## Summary

Ratifies user pick of Option B from Architect R5.2-research (`e8589e43-7bbf-4b87-8c26-1ee83e948c08`): every reactive HTML attribute binding in v1 `@template { … }` blocks MUST be `$`-prefixed (`$attr={expression}`). Plain curly form (`attr={expression}` without `$`) becomes a hard parse error in v1.0+ (error code **C306**). The Vue-shape `:attr="…"` (C304) and `@event="…"` (C305) legacy aliases are also rejected as hard errors. A new §11 Deprecation policy section catalogues all four error codes (C107 from v1.0.7, plus C304/C305/C306 from v1.0.8) with migration targets and authority citations.

---

## Rationale

User picked Option B over status-quo Option A and `bind:`-namespace Option C from Architect R5.2-research. Justification (per Architect §4):

1. **Uniformity.** Every other reactive surface form in v1 is `$`-prefixed (`$if`, `$each`, `$show`, `$on.`, `$bind.`, `$html`, `$ref`, `$once`, `$memo`, `$class`, `$raw`). Plain `attr={expr}` was the lone exception. Amendment 04 closes the gap.
2. **Grep-cleanliness.** `\$\w+=\{` now finds every reactive HTML binding with zero false positives. Component prop-passing (`<UserCard user={u} />`) keeps the plain curly form and does not collide.
3. **Modest migration cost.** 83 in-repo plain-curly sites identified by Investigator R5.1 §1.1; mechanical rewrite via `npx aihu migrate` in R5.2b-3.

Per Director r5-sup-2 §3.1, plain curly is rejected as a **hard error** in v1.0 (not deprecated-with-warning), because Option B's grep-cleanliness property depends on `$attr={…}` being the unambiguous reactive marker — a tolerated plain-curly exception would defeat the purpose.

## Acceptance criteria for downstream R5.2b-2 Builder

This Amendment 04 PR is the docs-only gate that unblocks R5.2b-2. The Builder's PR (`feat/v1-0-8-dollar-attr-parser-and-migrate`) MUST satisfy the following criteria, all of which cite Amendment 04 as authority:

1. **Parser accepts `$attr={expr}` and routes to `Attr::Binding`.** Per Director r5-sup-2 §3.2 implementation note: `$<plain-attr-name>={expr}` in `parse_macro_attr` (directives.rs:129-234) constructs `Attr::Binding { name, expr }` when `name` is NOT in the reserved-macro registry (`on.X`, `bind.X`, `class.X`, `if`, `each`, `key`, `show`, `once`, `memo`, `html`, `raw`, `ref`, `class`). When `name` IS in the registry, route to `Attr::Macro` as today. Document the registry as a private `const RESERVED_MACRO_NAMES` array.
2. **Parser rejects `:attr=` with C304.** Replace the deprecation branch at directives.rs:32-43 with a hard error emitting the verbatim message from spec §11.1: `` `C304: \`:<attr>=\` binding alias is removed in v1.0. Use \`$<attr>={expression}\` (one-way) or \`$bind.<attr>=\` (two-way) instead. Run: npx aihu migrate <file>` ``.
3. **Parser rejects `@event=` with C305.** Replace the deprecation branch at directives.rs:19-30 with a hard error emitting: `` `C305: \`@<event>=\` event-binding alias is removed in v1.0. Use \`$on.<event>=\` instead. Run: npx aihu migrate <file>` ``.
4. **Parser rejects plain `attr={expr}` with C306.** Replace the `Attr::Binding` construction branch at directives.rs:66-80 with a hard error emitting: `` `C306: \`<attr>={expression}\` plain-curly form is not permitted in v1.0; reactive HTML attribute bindings must be \`$\`-prefixed. Use \`$<attr>={expression}\`. Run: npx aihu migrate <file>` ``. The C306 rule MUST NOT fire on JSX-style prop-passing to author-defined components (capitalized tag names or `<$…>` structural elements) — discriminator is element-kind per spec §11.2.
5. **`Attr::Event` AST variant deleted.** Per Investigator R5.1 §4: delete the `Attr::Event { name: String, handler: String }` variant in `packages/compiler/src/types.rs:99-105` and the three match arms in `packages/compiler/src/codegen/emit.rs:1570, 3619-3622, 4070-4073`. `cargo check` must be green.
6. **`v1_rejections.rs` extended.** Three new conformance tests added (mirroring R5.2a's 10 existing tests): `rejects_legacy_event_binding_alias` (C304), `rejects_legacy_colon_binding_alias` (C305), `rejects_plain_curly_html_binding` (C306).
7. **`migrate.ts` extended with `migrateInlineAttrs` second pass.** Per Investigator R5.1 §6 (revised for Option B): regex rules for `@event=` → `$on.event=` (3 quote-style variants), `:attr=` → `$attr={…}` (2 quote-style variants, with leading-whitespace guard for `xmlns:`/`xlink:`), and plain `attr={x}` → `$attr={x}` (with leading-whitespace guard AND lowercase-tag-name lookbehind to skip JSX-style component prop-passes).
8. **`migrate.test.ts` extended with 8 new tests.** Covering: `@event=` rewrite (quoted/curly variants), `:attr=` rewrite (double-quoted/single-quoted), plain `attr={x}` rewrite on HTML elements, `<Component prop={x}>` NOT rewritten (JSX guard), `xmlns:xlink="…"` NOT rewritten (namespace guard), idempotency.
9. **Spec citation in PR description.** R5.2b-2 PR description MUST cite this Amendment 04 PR + spec §11 as the authority for the four reject codes.

The Builder MUST NOT rewrite `.aihu` source files in the workspace (those are R5.2b-3 territory).
