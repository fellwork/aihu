## THE BLOCKING DECISION: @aihu/context reconciliation â†’ OPTION C
Verified from source: `packages/context/src/index.ts` is DOM-FREE / module-level-Map / SSR-safe (`createContext`/`provide`/`inject`/`setSsrContextMap`/`clearSsrContextMap`/`runWithContext`), `.size-limit.json` row 300 B (Scout: 242 B actual, +51 B headroom). Consumers: `@aihu/router`, `@aihu-plugin/data`, `@aihu/server`. Plan 4 needs the OPPOSITE mechanism â€” a live DOM-walk ancestor traversal across shadow boundaries.

- A (DOM-walk into @aihu/context main): RULED OUT by dispatch (exceeds +51 B headroom >2x; breaks DOM-free/SSR thesis).
- B (`@aihu/context/dom` subpath): viable; favors vocabulary consistency; but keeps a colliding `createContext` symbol AND puts DOM-coupled code in a deliberately DOM-free package.
- **C (self-contained `createDomContext` in @aihu/primitives): CHOSEN.** New `packages/primitives/src/dom-context.ts`, distinct vocabulary (`createDomContext`/`provideContext`/`injectContext`), exported at `@aihu/primitives/context`, bundled into a `1 KB` primitives size row. Does NOT import `@aihu/context`.

**Rationale (crisp):** (1) DOM-walk is a behavior-layer concern (live custom elements over a real DOM tree) with no SSR-context meaning â€” wrong home for the SSR package. (2) Distinct vocabulary directly satisfies the master-spec anti-goal "no two competing createContext symbols" â€” Option B keeps the colliding name. (3) Zero coupling: @aihu/context's 300 B row + 3 consumers provably untouched because primitives never imports it. (4) Encapsulation â€” one cohesive primitives surface; SSR context stays orthogonal. Cost (two context APIs in the monorepo) is mitigated by the distinct names making the different mechanisms obvious at the call site.

**What flips if the user prefers B:** move `dom-context.ts` â†’ `packages/context/src/dom.ts`; add `"./dom"` to @aihu/context exports (mirror `./ssr`) + rolldown input; add @aihu/context to primitives `dependencies` + each primitive's size `ignore` list; rename factory to `createContext` (re-export from `@aihu/context/dom`); add a `@aihu/context/dom` (~150 B) size row + allowlist entry; drop the `@aihu/primitives/context` row. Tasks 4-11 consume the util BY INTERFACE (identical shape under B or C) â€” only import path + factory name differ. @aihu/context main row + ./ssr + 3 consumers stay untouched under BOTH options.
