# @aihu/editor — Architecture Spec

**Status:** proposed · **Author:** Architect agent · **Date:** 2026-07-22
**Decided upstream (not relitigated here):** hand-rolled on aihu primitives, no third-party editor
libraries; JSON document model is source of truth; serializes to both markdown and JSON; reusable
across apps; first consumer is the journal feature in fellwork/web
(`apps/web/src/components/journal/`).

**Grounding read:** aihu at `packages/{signals,arbor,runtime,agent,agent-service}` +
`docs/site/authoring-agents.md` (GX expose/describe, `$scope`, live-binding, fail-closed posture);
consumer at `apps/web/src/components/journal/markdown.ts` (the dialect-defining parser) and
`journal-entry.aihu` (current textarea editor, no-innerHTML block renderer).

## 1. Document model

### 1.1 Node kinds

The tree is deliberately shaped so that web's `Block[]` AST (`markdown.ts`) is a **near-projection**
of it — one mechanical map, no interpretation.

```ts
type DocNode = { schema: 'aihu-editor/doc'; version: 1; children: BlockNode[] }

type BlockNode =
  | { id: string; type: 'paragraph';  content: TextNode[] }
  | { id: string; type: 'heading';    attrs: { level: 1 | 2 | 3 }; content: TextNode[] }
  | { id: string; type: 'list';       attrs: { ordered: boolean }; children: ListItemNode[] }
  | { id: string; type: 'blockquote'; content: TextNode[] }            // dialect: inline-only, §8
  | { id: string; type: 'codeBlock';  attrs: { lang: string | null }; text: string }
  | { id: string; type: 'table';      children: [TableRowNode, ...TableRowNode[]];
                                      attrs: { aligns: ('l'|'c'|'r')[] } } // row 0 is the header
  | { id: string; type: 'hr' }

type ListItemNode = { id: string; type: 'listItem'; content: TextNode[] }
type TableRowNode = { id: string; type: 'tableRow'; children: TableCellNode[] }
type TableCellNode = { id: string; type: 'tableCell'; content: TextNode[] }

// Inline: flat runs of text carrying at most ONE mark (see invariant I4).
type Mark =
  | { type: 'strong' } | { type: 'em' } | { type: 'code' }
  | { type: 'link'; attrs: { href: string } }
type TextNode = { text: string; mark: Mark | null }
```

Marks are **data on text runs**, not nested inline nodes — exactly web's `InlineRun` shape
(`{t, s, href?}`). `TextNode` has no `id`; identity is positional within its block.

### 1.2 Addressing & selection

Positions are **(blockId, charOffset)**, not tree paths and not ProseMirror flat tokens:

```ts
type Point = { block: string /* BlockNode|ListItemNode|TableCellNode id */,
               offset: number /* char offset into the flattened inline text (mark-transparent) */ }
type SelectionState =
  | { type: 'caret';  at: Point }
  | { type: 'range';  anchor: Point; head: Point }   // anchor = where drag started
  | { type: 'node';   block: string }                // hr, whole-table selection
```

Rationale: block ids are stable across sibling insert/remove (a path `[3]` is not), they double as
`$each` keys (web already requires stable `k` keys for its keyed renderer), and offsets that ignore
mark boundaries survive `applyMark` without remapping. Every step (§2) documents how it maps a
`Point` forward (`mapPoint(step, p): Point`); the history and future collab both rely on this.

### 1.3 Invariants (validated after every transaction; violation = rejected transaction)

- **I1** `doc.children.length >= 1`; an "empty" doc is `[paragraph []]`.
- **I2** Every `id` is unique in the doc, generated once at node creation (`b_<base36 counter+entropy>`),
  never regenerated by edits — this is what keeps re-render keyed and undo cheap.
- **I3** Adjacent `TextNode`s with equal `mark` are merged; no empty `text: ''` runs
  (normalization pass, part of `applyTransaction`).
- **I4 (dialect guard)** At most one mark per run; `link` hrefs must pass `safeHref` (§6).
  Web's regex-based inline parser cannot express nested/overlapping marks (`***x***` mis-parses),
  so the model refuses to create what the wire format cannot carry. Applying a second mark
  replaces the first. Lifted later only when the dialect grows (§8).
- **I5** Heading levels clamp to 1–3 (web clamps at parse; we clamp at write).
- **I6** `table.children[n].children.length === attrs.aligns.length` for all rows (rectangular).
- **I7** `schema`/`version` are present on every persisted doc; loaders run
  `migrate(doc): DocNode` — v1 loaders reject unknown major versions, forward-migrate known ones.

### 1.4 Known mismatches vs web's Block AST (explicit, so nobody rediscovers them)

| Doc model | web `markdown.ts` | Resolution |
|---|---|---|
| `listItem.content` could nest blocks | items are inline-only | MVP restricts listItem to inline (dialect guard); nested lists are v-next + dialect change |
| `blockquote` could nest blocks | quote folds `>` lines into one inline run | MVP: inline-only blockquote |
| `codeBlock.attrs.lang` | fence info string dropped | serializer emits ` ```lang `; web tolerates and ignores — lossless for us, invisible to web |
| text may contain `*_\`[|` literally | **no backslash-escape support in the parser** | §8.2 — requires a small upstream patch to `markdown.ts`; founder call |
| `heading` 1–3 only | clamps 4–6 → 3 | aligned by I5 |

## 2. Edit pipeline — transactions and steps

Every mutation — keystroke, paste, toolbar, input rule, **agent call** — is a serializable
transaction applied through one function. There is no second door.

```ts
interface Transaction {
  id: string
  time: number
  origin: 'user.typing' | 'user.command' | 'user.paste' | 'inputrule'
        | 'history' | `agent:${string}` | 'load'
  steps: Step[]
  selectionAfter?: SelectionState
}

type Step =
  | { t: 'insertText';  at: Point; text: string; mark: Mark | null }
  | { t: 'deleteRange'; from: Point; to: Point }                  // same block
  | { t: 'setMark';     from: Point; to: Point; mark: Mark | null }
  | { t: 'splitBlock';  at: Point; newId: string }
  | { t: 'mergeBlock';  first: string; second: string }
  | { t: 'insertBlock'; after: string | null; node: BlockNode }   // null = doc start
  | { t: 'removeBlock'; id: string }
  | { t: 'setBlockType'; id: string; type: BlockNode['type']; attrs?: object; newId?: string }
  | { t: 'setAttrs';    id: string; attrs: object }

interface EditorCore {
  apply(tr: Transaction): ApplyResult            // validate → mutate → normalize → notify
  invert(step: Step, docBefore: DocNode): Step   // total: every step has an exact inverse
  onTransaction(cb: (tr: Transaction, doc: DocNode) => void): Dispose
  doc: Read<DocNode>                             // an @aihu/signals signal — effect()/computed() compose
  selection: Read<SelectionState>
}
```

`apply` is: structural validation (unknown ids, bad offsets → reject whole tr) → step-by-step
mutation → normalization (I3) → invariant check → set `doc` signal inside `batch()` → fire
`onTransaction`. Rejection returns `{ ok: false, code, step }`; it never partially applies.

**Undo/redo** is an in-core history stack of `{ steps: Step[], inverse: Step[], selBefore, selAfter,
origin }`. Grouping: a new entry **coalesces** into the previous one when `origin === 'user.typing'`,
same block, offsets contiguous, and Δt < 1000 ms; any other origin (paste, input rule, agent) is
always its own entry. Undo applies `inverse` reversed as a tr with `origin: 'history'` (which the
history itself ignores). Agent transactions sit in the *same* stack — a human can undo an agent
edit and vice versa; that symmetry is thesis-load-bearing (§7).

**What this buys later:** steps are serializable, invertible, origin-attributed, and have a
`mapPoint` — the exact substrate OT/CRDT rebasing needs. Collab is out of scope (§10) but nothing
here has to be redesigned for it.

## 3. View layer

### 3.1 Package shape

`@aihu/editor` ships two layers:

- **`EditorCore`** — plain TS (model + transactions + serializers), zero DOM, fully unit-testable
  in vitest/jsdom without contenteditable. This is also what a server or agent test harness drives.
- **`EditorView`** — DOM layer binding one `EditorCore` to one `contenteditable` root.
- **`editor.aihu`** — the `<aihu-editor>` SFC (§9): chrome, props, GX surface; owns an `EditorView`.

### 3.2 contenteditable strategy

- One `contenteditable="true"` region (`role="textbox"` `aria-multiline="true"`), light DOM.
- **`beforeinput` (Input Events Level 2) is the interception point. Never `execCommand`.**
  Handler: if composing (§4) → do nothing; else `preventDefault()` and translate `inputType` to
  commands: `insertText`, `insertParagraph`, `insertLineBreak`, `deleteContentBackward`,
  `deleteContentForward`, `deleteByCut`, `deleteWordBackward`, `formatBold`, `formatItalic`,
  `insertFromPaste`/`insertFromDrop` (§6), `historyUndo`/`historyRedo` (routed to our history).
  Unknown `inputType` → preventDefault + no-op (fail closed; log in dev).
- The browser is **never** allowed to mutate the editable DOM outside composition. A
  `MutationObserver` on the root is the tripwire: any uncontrolled mutation triggers **read-back
  reconciliation** (§4.3) rather than being trusted or discarded.

### 3.3 Rendering — aihu/arbor idioms, block-granular

The editable subtree is **owned imperatively by `EditorView`**, built from `@aihu/arbor`
`branch`/`leaf` primitives — not from `@template each={}`. Reason: the SFC template pipeline
re-creating nodes would fight native selection and IME; arbor's `leaf` binds text to
`textNode.nodeValue` (the runtime's documented fast path), which is exactly the granularity
typing needs. The `@template` of `editor.aihu` renders chrome only (toolbar slot, placeholder,
suggestion affordances) around an `<div data-aihu-editor-surface>` mount point.

- Each `BlockNode` renders to one element stamped `data-block-id={id}` via a per-type
  `BlockRenderer`. A registry `Map<type, BlockRenderer>` mirrors web's per-type template arms.
- On transaction, only blocks named in the tr's **touched-id set** re-render; a pure
  `insertText`/`deleteRange` step patches the affected text nodes' `nodeValue` in place
  (no element churn ⇒ selection survives without restoration in the common case).
- Block insert/remove/reorder is keyed by `id` — same reconciliation discipline as web's `$each key`.
- After every apply, `EditorView` writes the model selection back to the DOM
  (`Selection.setBaseAndExtent`) iff the DOM selection differs (guard against loops).
- **No HTML sink**: renderers use `document.createElement`/`createTextNode` only. CI greps the
  package for `innerHTML|outerHTML|insertAdjacentHTML|srcdoc` → must be 0 outside the inert
  paste parser (§6).

### 3.4 Light vs shadow DOM

`shadowMode: 'light'` is **required** (the runtime supports it via `define-element.ts`; DA4 #437
makes it the default direction). `document.getSelection()` does not pierce shadow roots portably
(Safari's `getComposedRanges` is too new to gate on), and IME positioning inside shadow roots is
inconsistent. Style scoping falls back to the compiler's scoped-class output rather than shadow
encapsulation — same trade web components in fellwork/web already make.

## 4. Selection & IME

### 4.1 Selection sync

One `selectionchange` document listener (active while focus is inside the surface):
DOM `Range` → find ancestor `[data-block-id]` → walk that block's text nodes accumulating
`nodeValue.length` to a char offset → `SelectionState` → set `selection` signal (skip if equal).
The inverse mapping (model → DOM) walks the same order. Both directions live in one module
(`position-map.ts`) with property tests: `toDom(toModel(r)) ≡ r` for all ranges over a fuzzed doc.

### 4.2 Composition (IME)

- `compositionstart` → `composing = true`; from here the browser owns the DOM inside the active
  block. `beforeinput` with `inputType: 'insertCompositionText'` is **never** prevented; all other
  interception is suspended for that block.
- `compositionend` → read the composed block's DOM text, **diff against the model block**
  (single-block char diff), synthesize one `insertText`/`deleteRange`+`insertText` transaction
  with `origin: 'user.typing'`, then re-render the block from the model (DOM becomes canonical
  output of model again). `composing = false`.

### 4.3 Known hard cases & mitigations

| Case | Failure mode | Mitigation |
|---|---|---|
| Safari IME | `compositionend` fires before the final mutation; stale read-back | read-back is scheduled on `requestAnimationFrame` after `compositionend`, and the MutationObserver queue is drained first |
| Android GBoard backspace | no clean `deleteContentBackward`; deletions arrive as composition on the whole word | never trust inputType on Android during composition; rely wholly on compositionend diffing. The diff, not the event, is the truth |
| Uncontrolled mutation (spellcheck replace, autofill, extensions) | DOM ≠ model silently | MutationObserver → same read-back reconciliation path as compositionend; synthesized tr with `origin: 'user.typing'` |
| Selection restore during composition | caret jumps inside IME window | model→DOM selection writes are suppressed while `composing` |

Read-back reconciliation (one block, diff, synthesize tr) is the single recovery mechanism for
every "browser did something we didn't mediate" case — one code path to harden, not four.
(Concept borrowed from ProseMirror's DOMObserver, reimplemented; see §11.)

## 5. Input rules (markdown-ish autoformat)

```ts
interface InputRule {
  id: string                       // 'heading', 'bullet', 'strong', 'code-fence', …
  scope: 'blockStart' | 'inline'
  trigger: string                  // char whose insertion arms the check: ' ' , '`', '*', '_', 'Enter'
  match: RegExp                    // applied to block text [0, caret); must end at caret
  apply(m: RegExpExecArray, ctx: { blockId: string; caret: Point }): Step[]
}
```

Engine: runs after an `insertText` commit whose text ends with a rule's trigger; first matching
rule wins; the emitted steps are applied as a **separate transaction** with `origin: 'inputrule'`
so a single undo restores the literal typed text (`# x` comes back as `# x`, PM-style).

Built-in registry (each individually disableable):

| id | scope | typed | result |
|---|---|---|---|
| `heading` | blockStart | `#`–`###` + space | `setBlockType heading{level}` + delete prefix |
| `bullet` | blockStart | `-`/`*` + space | list(ordered:false) wrap |
| `ordered` | blockStart | `1.`/`1)` + space | list(ordered:true) wrap |
| `quote` | blockStart | `>` + space | blockquote |
| `fence` | blockStart | ` ``` ` (+lang) + Enter | codeBlock{lang} |
| `hr` | blockStart | `---` + Enter | hr + fresh paragraph |
| `strong` | inline | `**x**` / `__x__` | setMark strong, delimiters deleted |
| `em` | inline | `*x*` / `_x_` | setMark em |
| `code` | inline | `` `x` `` | setMark code |

Declaration/disabling: `features` prop (§9) — `inputRules: false` kills the engine;
`inputRules: { disable: ['hr','fence'] }` prunes; hosts may `editor.registerInputRule(rule)`
(consumer-defined rules run after built-ins). Rules never run while `composing`, never inside
`codeBlock`, and never on `origin: 'agent:*'` transactions (agents state intent via steps, not
via typing simulation).

## 6. Security posture

Doctrine inherited from web's `markdown.ts` and kept absolute: **there is no HTML sink anywhere in
the pipeline** — not in rendering (§3.3), not in paste, not in serialization.

### 6.1 Paste pipeline (`insertFromPaste`, also `insertFromDrop`)

1. Prefer `clipboardData.getData('text/html')`; fall back to `text/plain` (split on blank lines →
   paragraphs; done).
2. Parse HTML with `new DOMParser().parseFromString(html, 'text/html')` — an **inert document**:
   scripts don't run, resources don't load, nothing is ever attached to the live DOM.
3. **Allowlist walk** (`paste-sanitize.ts`), building doc nodes directly — never re-serializing
   to HTML: elements in {`p,div,h1..h6,ul,ol,li,blockquote,pre,code,b,strong,i,em,a,br,hr,
   table,thead,tbody,tr,th,td,span`} map to nodes/marks; **every other element contributes only
   its text content**; **every attribute is dropped** except `a[href]`.
4. `href` passes **the same `safeHref` contract as web** (`/…` same-origin, `https?://`, `mailto:`;
   everything else — `javascript:`, `data:`, `vbscript:`, protocol-relative `//` — drops the link,
   keeps the label as text). Shipped as `@aihu/editor/safe-href` so web can converge on one
   implementation later.
5. Resulting fragment inserted via ordinary `insertBlock`/`insertText` steps,
   `origin: 'user.paste'` — so paste is validated by the same invariants, undoable as one unit,
   and visible to observers like any other edit.

### 6.2 XSS threat model

| # | Vector | Enters via | Defense |
|---|---|---|---|
| T1 | `<script>`/handler attrs in pasted HTML | paste | inert DOMParser + allowlist drops elements and all attrs |
| T2 | `javascript:`/`data:` href | paste, typed `[x](…)`, agent `applyMark link` | `safeHref` at **model write time** (invariant I4), not render time — a bad href cannot exist in the doc |
| T3 | Stored XSS through serialized markdown re-rendered at `/shared/journal/<slug>` | serialization | serializer emits only dialect constructs; web's renderer has no HTML sink; escaping per §8.2 |
| T4 | HTML injection via rendering | render | no innerHTML anywhere; CI grep gate |
| T5 | CSS/style smuggling (`style=`, `<style>`) | paste | attributes dropped; `<style>` not in allowlist |
| T6 | Agent-injected content (malicious tool caller) | GX actions | agent steps run through the identical `apply()` validation + safeHref + invariants as keystrokes (§7); scope/rate-limit fail closed upstream |
| T7 | Markdown structure injection (text that becomes markup on serialize, e.g. a line of `---` or `| a |`) | typing, paste, agent | serializer escaping rules §8.2 make text runs inert |

CSP-clean: no `eval`, no `new Function`, no inline event handlers, no dynamic script/style —
compatible with `script-src 'self'` and a no-`unsafe-inline` policy.

## 7. AI governance surface (GX) — the flagship

The editor's differentiator: the **same transaction pipeline serves the keyboard and the agent**,
and the GX layer (`expose`/`describe` on `@state` entries → `agent-manifest` → `@aihu/agent-service`
live-binding) makes the agent's half *governed, scoped, and attributable* — "equal governance of
humans and AI" made concrete in one component.

### 7.1 Exposed surface (declared in `editor.aihu` `@state`, GX v2 grammar)

Read tier (`expose: { read: true }`):

- `doc` — derived; `describe: 'The current document as canonical aihu-editor JSON (schema/version/children)'`
- `docMarkdown` — derived; the dialect serialization (§8)
- `selectionContext` — derived; `{ selection, textAround }` so an agent can ground "insert here"
- `docOutline` — derived; headings + block ids, the cheap map an agent reads before editing

Write tier (`expose: { read: true, write: true }`) — **all write actions take steps/nodes, are
validated by `EditorCore.apply` exactly as human input, and land in the shared undo history with
`origin: 'agent:<tool>'`**:

- `insertBlock({ after: blockId | null, node: BlockNode })`
- `replaceRange({ from: Point, to: Point, text: string })`
- `applyMark({ from: Point, to: Point, mark: Mark | null })`
- `setBlockType({ id, type, attrs })`
- `applyTransaction({ steps: Step[] })` — the power tool; same validation, atomic
- `setDoc({ doc: DocNode })` — full replace; guarded (below)

Each action's `describe:` names its **failure contract** (invalid ids/offsets/hrefs → structured
`{ ok:false, code }`, never partial application), so the emitted MCP tool schema teaches the
agent the invariants instead of letting it discover them by corruption.

### 7.2 Host scoping — how an app decides what an agent may do

Three cooperating controls, layered fail-closed:

1. **Component knob** — `agentAccess` prop on `<aihu-editor>`:
   `'none' | 'read' | 'suggest' | 'write'`. Live-binding action dispatch checks it first;
   `'none'` unregisters the binding entirely. **Default: `'read'`** — an embedding app gets
   agent *legibility* for free but must opt into agent *authorship*.
2. **`'suggest'` mode (the thesis showcase)** — agent write actions are accepted, validated,
   but **staged**: held as pending transactions rendered as inline suggestions (block-level
   affordance in the chrome, styled per-origin), with human Accept (applies with
   `origin: 'agent:<tool>'` preserved) / Reject. The human governs; the agent proposes through
   the same typed channel it would use to write.
3. **Service layer (existing GX machinery, unchanged)** — `@agent { $scope "…" $rate-limit n }`
   on the embedding page component; `@aihu/agent-service` enforces JWT scope (401/403),
   rate-limit (429, fails closed when the plugin is absent — GO1), the 404→401→403→429 error
   ordering, and client-bundle elision of `__agentBinding`.

### 7.3 Equal-governance invariants (testable)

- **G1** No agent-only door: every state reachable by an agent action is reachable by some human
  edit sequence, and both flow through `apply()` — one validator, one history, one observer feed.
- **G2** Symmetric undo: human undo reverts agent transactions and vice versa.
- **G3** Attribution is total: every transaction has an `origin`; the `transaction` event exposes
  it; an audit log is `onTransaction` + a sink, no extra hooks.
- **G4** Governance fails closed: unknown action → error; `agentAccess` missing → `'read'`;
  scope declared but auth plugin absent → 401 (inherited).

## 8. Serialization

### 8.1 Formats

- **`toJSON(doc)`** — canonical: the `DocNode` itself (schema + version + children), stable key
  order, no undefineds. What persistence and agents see.
- **`toMarkdown(doc)`** — **dialect-locked to web's parser** (`markdown.ts` is the normative
  grammar; a fixture corpus of `(doc, md, blocks)` golden triples in-repo is the contract).
  Emission rules: paragraphs joined by blank lines; headings `#{level} `; lists `- ` / `1. `
  (renumbered); blockquote `> ` single logical line; fences with lang; `---`; pipe tables with
  alignment row from `attrs.aligns`; marks as `**x**` `*x*` `` `x` `` `[label](href)`.
- **`fromMarkdown(md)`** — import; a port of web's parser semantics producing `DocNode` directly
  (line-based, same clamps, same table/alignment rules). Web's `parseMarkdown` stays where it is
  for now; convergence on the editor's parser is a later, separate decision.
- **Round-trip guarantee (acceptance-tested):** `toMarkdown(fromMarkdown(m))` is
  byte-identical for any `m` already in normal form, and
  `fromMarkdown(toMarkdown(d))` ≡ `d` (modulo ids) for any valid dialect-guarded doc.

### 8.2 Escaping — a real finding, needs an upstream patch

Web's parser has **no backslash-escape handling**: there is currently no way to serialize literal
`*a*`, `` ` ``, `[x](y)`, a cell containing `|`, or a paragraph line of `---` without it
re-parsing as markup (threat T7, and a silent round-trip corruption). Options:

- **(A, recommended)** Patch `markdown.ts` to honor `\` before `` * _ ` [ ] | `` (≈10 lines in
  `parseInline` + table `splitRow`; backwards compatible for all stored bodies that contain no
  backslash-escapes today). Editor serializer then escapes those characters in text runs, plus
  line-start escapes for `#`, `>`, `-`, `1.`, `---` when they'd be structural.
- (B) Live with lossy degradation: serializer inserts nothing, documents that literal dialect
  characters may re-parse. Rejected as default — violates round-trip and T7.

**(A) touches the rendering of stranger-visible stored content in web → founder sign-off (§ final
report).** Until it lands, the serializer runs in mode (B) behind a `dialect: 'web-v1'` flag with
the corruption cases enumerated in tests as `expected-lossy`.

JSON-only constructs degrade on `toMarkdown`: `codeBlock.lang` survives (ignored by web);
multi-mark runs cannot exist (I4); node types outside §1.1 cannot exist (v1 schema is closed).

### 8.3 Rust/WASM serializer — evaluated, deferred

The compiler is Rust, and an edge/Fly service (e.g. rendering shared journal entries
server-side) might want the same serializer. Verdict: **do not block on it.** The TS
implementation is normative; the golden-fixture corpus (§8.1) is deliberately
language-neutral JSON+MD files, so a later `aihu-editor-serde` crate (native + wasm32) can be
proven conformant mechanically. Revisit when a server consumer actually exists.

## 9. Component surface

### 9.1 `<aihu-editor>`

Props (GX `describe:` on each):

| Prop | Type | Notes |
|---|---|---|
| `doc` | `DocNode \| null` | initial/controlled JSON; wins over `markdown` |
| `markdown` | `string` | convenience init via `fromMarkdown` |
| `readonly` | `boolean` | render-only; commands and beforeinput disabled |
| `features` | `FeaturesConfig` | `{ headings?, lists?, blockquote?, codeBlock?, table?, link?, inputRules? }` — off ⇒ commands rejected, paste content degrades to text, rules pruned |
| `agentAccess` | `'none'\|'read'\|'suggest'\|'write'` | §7.2; default `'read'` |
| `placeholder` | `string` | empty-doc hint |

Events (CustomEvent, composed):

- `transaction` — every applied tr: `detail: { tr, doc }` (the `$subscribe`-grade feed)
- `change` — debounced (150 ms trailing): `detail: { doc, markdown }`
- `editor-selectionchange` — `detail: SelectionState`
- `agent-suggestion` — suggest-mode staging/accept/reject lifecycle

Element API (for hosts and the toolbar): `exec(command: Command): boolean`,
`can(command): boolean`, `getJSON(): DocNode`, `getMarkdown(): string`,
`setDoc(doc)`, `focus()`. `Command` is the closed union the toolbar and GX actions share
(`{ type: 'toggleMark', mark } | { type: 'setBlockType', … } | …`).

### 9.2 Toolbar — separate, composable

`<aihu-editor-toolbar for="…">` (or slotted child): finds its editor, renders from the editor's
exported `activeState` signal (`{ marks: Set, blockType, canUndo, canRedo }`), and talks **only**
through `exec`/`can`. No private coupling — a host can replace it entirely; the toolbar works
against anything implementing the element API.

### 9.3 Journal embedding (first consumer)

`journal-entry.aihu` swaps its `<textarea class="bin">` for:

```html
<aihu-editor
  markdown={dBody}
  features={{ table: true, codeBlock: true }}
  agentAccess="suggest"
  on:change={(ev) => { dBody = ev.detail.markdown }} />
```

Save path is unchanged: `patchEntry(id, { body_md: dBody })`. "Add note"/"Add table" become
`ed.exec({ type: 'insertMarkdown', md: noteSnippet() })` instead of string concatenation. The
read view keeps rendering via web's own parser — which is the round-trip contract exercised in
production on every save.

## 10. Phasing & acceptance

### Phase 0 — de-risk spike (before MVP is committed)

Throwaway harness proving §4 on the matrix {Chrome, Safari, Firefox} × {desktop} + {iOS Safari,
Android Chrome+GBoard}: typed ASCII, IME (Japanese + Korean), GBoard backspace, spellcheck
replace. Exit criterion: read-back reconciliation recovers model≡DOM in all cases. If a browser
class fails irrecoverably → invoke the §11 fallback before building more.

### MVP (v1) — scope

Paragraphs, headings 1–3, strong/em/inline-code, links (typed via input rule + command),
flat bullet/ordered lists, blockquote, hr, undo/redo, markdown round-trip, paste
(plain + sanitized HTML), toolbar, GX read tier + `insertBlock`/`replaceRange`/`applyMark` +
`agentAccess` knob ('suggest' UI may be minimal: accept/reject bar).

Runnable acceptance criteria (Verifier-executable; core ones run headless against `EditorCore`,
view ones in the Phase-0 harness):

- **A1** Fresh editor, type `# Hello` then Enter then `world` ⇒ `getJSON().children` ≡
  `[heading{level:1}[text 'Hello'], paragraph[text 'world']]`; `getMarkdown()` ≡ `"# Hello\n\nworld"`.
- **A2** Type `**bold**` ⇒ run `{text:'bold', mark:strong}`, delimiters gone; one undo ⇒ literal
  `**bold**` text restored.
- **A3** Type 12 chars, one undo ⇒ empty paragraph (coalescing); pause > 1 s mid-word ⇒ two undo
  steps.
- **A4** `fromMarkdown(toMarkdown(d)) ≡ d` (mod ids) over the golden corpus incl. every §1.1
  node type; and over 1 000 fuzzed dialect-guarded docs (fast-check, matching repo practice).
- **A5** Paste `<script>alert(1)</script><p onclick=x>hi <a href="javascript:alert(1)">l</a></p>`
  ⇒ doc contains exactly `paragraph[text 'hi ', text 'l']`; no script element ever attached
  (assert via MutationObserver on `document`).
- **A6** `element.getMarkdown()` output fed to web's `parseMarkdown` yields blocks structurally
  equal to `toBlocks(getJSON())` (the projection of §1.1) — run against web's actual
  `markdown.ts` in CI (fixture-shared, not vendored).
- **A7** Agent path: `handleToolCall('aihu-editor/insertBlock', {after:null, node:paragraph})`
  with `agentAccess='write'` mutates the doc; same call with `'read'` ⇒ structured denial and doc
  unchanged; with `'suggest'` ⇒ doc unchanged until accept; human Ctrl-Z after accept reverts it (G2).
- **A8** Grep gate: zero `innerHTML|outerHTML|insertAdjacentHTML` matches in `src/` outside
  `paste-sanitize.ts`'s inert-DOMParser call.
- **A9** IME: harness composes 日本語 mid-paragraph ⇒ model equals DOM text, caret correct, no
  transaction emitted before `compositionend`.

## 11. Risks & alternatives

Ranked hardest problems:

1. **IME / Android text input** (probability high, severity high). The event stream is unreliable
   by platform. Mitigation: composition = browser-owned + compositionend diff (§4.2); read-back
   reconciliation as the universal recovery path; Phase-0 spike **before** MVP commitment; the
   diff-based recovery means even unknown platform behavior degrades to "model catches up",
   not corruption.
2. **DOM↔model position mapping drift** (medium, high). Every selection bug is here. Mitigation:
   one module owns both directions; property-tested round-trip (§4.1); blockId+offset (not paths)
   shrinks the mapping surface to a single block walk; `nodeValue` patching avoids most
   restore-selection churn.
3. **Paste fidelity** (high probability, medium severity — security is handled by construction,
   fidelity is the risk). Word/GDocs/Notion HTML is hostile garbage. Mitigation: allowlist
   collapses unknowns to text (never blocks paste entirely); golden corpus of real-world clipboard
   captures; worst case is "pasted as plain text", which is the documented floor.

**Fallback if contenteditable proves intractable in a browser class:** feature-flagged
degradation to a **plain `<textarea>` markdown mode** — the journal's current editor, kept alive
inside `<aihu-editor>` as `mode: 'source'` sharing the same props/events/serializers (`change`
still emits `{doc, markdown}` via `fromMarkdown`). Consumers lose WYSIWYG on that platform,
never data or the API contract. This also gives every user a source-view escape hatch for free.

**Stolen conceptually from ProseMirror (no code):** transactions-of-invertible-steps with
position mapping; "browser owns the DOM during composition, reconcile after" via a
DOMObserver-style read-back; input-rule undo restoring literal text; schema-validated single
apply path. **Deliberately not taken:** flat token positions (we use blockId+offset), nested-mark
inline model (dialect forbids it), plugin-transaction metadata system (origins + features config
cover our cases at a fraction of the surface).
