Branch: `fix/protocol-conformance`. Founder decision (REVERSED via /autoplan,
2026-07-20): **A2A conformance only; deprecate `@aihu/agent-acp`** — BeeAI ACP
merged into A2A under the Linux Foundation (Aug 2025); Zed owns the "ACP" name

## Spec citation

Conformance target: **Agent2Agent (A2A) Protocol Specification v1.0.1**
(latest release, 2026-05-28) — <https://a2a-protocol.org/v1.0.1/specification>,
**JSON-RPC 2.0 binding** (spec §9). Verified against the live spec sources
during this build:

- `https://raw.githubusercontent.com/a2aproject/A2A/main/docs/specification.md`
  (method names §9.4, error mappings §5.4, JSON naming §5.5, well-known URI §13)
- `https://raw.githubusercontent.com/a2aproject/A2A/main/specification/a2a.proto`
  (Task/Message/Part/AgentCard field-level shapes)
- `https://github.com/a2aproject/A2A/releases` (version check: v1.0.0
  2026-03-12, v1.0.1 2026-05-28)

Key confirmations that differ from the issue's provisional guesses: the v1.0
JSON-RPC methods are **PascalCase** (`SendMessage`, `SendStreamingMessage`,
`GetTask`, `ListTasks`, `CancelTask`, `SubscribeToTask`, `GetExtendedAgentCard`)
— the `message/send`-style names were the 0.2/0.3 wire. Enums serialize as
ProtoJSON names (`ROLE_USER`, `TASK_STATE_COMPLETED`); fields are camelCase.
Card path is `/.well-known/agent-card.json`. The card's endpoint pointer is
`supportedInterfaces[]` (url + protocolBinding + protocolVersion), not a bare
`url` field.

## Part B — `@aihu/agent-a2a` conformance (path taken: **CONFORMED**)

Full conformance was achievable in this pass: the surface is one adapter over
an already-solid `AgentService` gate, and the spec's mandatory JSON-RPC surface
is small. No half-conversion; no design-spec fallback needed.

### Implementation (`packages/agent-a2a/src/`)

| File | Content |
|---|---|
| `types.ts` | A2A v1.0.1 data model (camelCase JSON, ProtoJSON enums): `Task`, `TaskStatus`, `TaskState`, `Message`, `Part`, `Artifact`, `TaskStatusUpdateEvent`, `TaskArtifactUpdateEvent`, `StreamResponse`, `AgentCard`, `AgentInterface`, `AgentCapabilities`, `AgentCardSkill`, JSON-RPC envelope types, `TaskStore` interface, `A2aAdapterOptions` |
| `task-store.ts` | `createInMemoryTaskStore()` — default `TaskStore`; injectable via `options.taskStore` |
| `a2a-adapter.ts` | The adapter: agent card + JSON-RPC endpoint + SSE streaming + task lifecycle |

### Old wire → new wire mapping

| 0.1.x shim | v1.0.1 conformant |
|---|---|
| `GET /.well-known/agent.json` | `GET {prefix}/.well-known/agent-card.json` — REQUIRED fields incl. `supportedInterfaces[{url, protocolBinding: "JSONRPC", protocolVersion: "1.0"}]`, skills with REQUIRED `id`/`name`/`description`/`tags` |
| `POST /a2a/tasks/send` `{taskId?, message: "tag/action", params}` | `POST {prefix}/a2a` JSON-RPC `SendMessage` with `params.message` (typed `parts`) |
| `body.message` literal `"tag/action"` string | data part `{ "data": { "skill": "<tag>/<action>", "params": {…} } }`, or a text part whose text is the skill id (params from first data part) |
| `POST /a2a/tasks/sendSubscribe` — pre-rendered string + `[DONE]` | `SendStreamingMessage` — real `ReadableStream` SSE; every frame a full JSON-RPC response wrapping `StreamResponse` (`task` → `statusUpdate` working → `artifactUpdate` → terminal `statusUpdate`); terminality is the state, no sentinel |
| `tasks/get` unimplementable (no store) | `GetTask` (with `historyLength` semantics, `-32001` TaskNotFound), `ListTasks` (contextId/status filter, pageSize), `CancelTask` (`-32002` on terminal, real cancel on interrupted states) — all backed by the `TaskStore` |
| — | `SubscribeToTask` (`-32001`/`-32004` per §9.4.6; replays current status for non-terminal), push-config methods → `-32003`, `GetExtendedAgentCard` → `-32007` |
| `capabilities.streaming` hardcoded on an endpoint that didn't stream | `capabilities: { streaming: true (real), pushNotifications: false, extendedAgentCard: false }` |
| `{error: 'bad message'}` ad-hoc 400s | JSON-RPC errors per §9.5/§5.4: `-32700` parse, `-32600` invalid request, `-32601` method not found, `-32602` invalid params with `@type` `google.rpc.BadRequest` fieldViolations |

Gate verdict mapping (attribution preserved, AT1): 401 `AUTH_REQUIRED` →
`TASK_STATE_AUTH_REQUIRED` (interrupted — re-sending with `message.taskId` +
credentials resumes the same task, proven by test); 403 `SCOPE_DENIED` →
`TASK_STATE_REJECTED`; other gate failures → `TASK_STATE_FAILED`. The full gate
envelope (`{error, code, jsonrpc}`) rides in a status-message data part so the
verdict stays auditable at the transport boundary.

`AgentCardSkill` (not `AgentSkill`/`A2aSkill`) because `check:derived` D1
forbids re-declaring an exported agent-surface type name already used by
`@aihu-plugin/agent-readiness` (`AgentSkill` in mcp-server-card.ts, `A2aSkill`
in a2a-card.ts).
