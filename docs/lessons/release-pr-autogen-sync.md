# Release-PR autogen artifact regen

**Topic:** aihu-v1-framework
**Round:** 7
**Category:** release-engineering, ci-architecture
**Severity:** medium (historic — now structurally fixed)

## The lesson

When a Release-PR is auto-generated by changesets (or any similar version-bump tool), the version step runs in a fresh CI checkout. Any autogenerated artifact that depends on `package.json` content (READMEs synced from JSDoc, generated TypeScript declarations, lockfiles, etc.) MUST be regenerated INSIDE the Release-PR workflow's version step, not assumed-current from the developer's last local run.

If you don't, the Release-PR commits stale autogen artifacts. The PR looks clean (CI passes, version bumped, changelog updated), but the README/d.ts/lockfile in the PR doesn't reflect the new versions — and developers reviewing the PR have no way to spot it without running the regen tool themselves.

## How it bit us this session

`sync-readme.ts` regenerated each package's README from JSDoc + `package.json` metadata. It ran in pre-commit hooks locally but NOT in the Release-PR workflow. Result: every Release-PR for ~8 weeks had a "Last Updated" footer and version-pin block that lagged 1-2 versions behind reality. Caught during the v1.0.8 docs review.

## The fix (already shipped)

`.github/workflows/release-pr.yml`'s version step now runs:

```yaml
- name: Version + regen autogen
  run: |
    bun install --frozen-lockfile
    bun changeset version
    bun install                  # refresh lockfile after version bumps
    bun run sync-readme          # regen READMEs against new versions
    git add -A
```

The `bun install` between `changeset version` and the regen tool is non-obvious but critical: changesets edits `package.json` files, and `sync-readme.ts` reads `node_modules/<pkg>/package.json` for cross-package metadata, which is stale until `bun install` resolves the new versions.

## The rule

Any autogen tool that reads `package.json` (this package or a sibling's) MUST run in the Release-PR workflow's version step, AFTER `changeset version` AND AFTER a fresh `bun install` to resolve the new versions. Add a check that `git diff` is empty at the end of the version step (failing on uncommitted regen output) to catch new autogen tools that haven't been wired in.
