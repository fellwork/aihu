# Deployment

## Bun (recommended)

```bash
bun run build
bun run preview
```

`bun run build` compiles all `.aihu` SFCs, bundles with Vite/Rolldown, and validates size budgets. `bun run preview` serves the production build locally using Bun's built-in HTTP server.

## Node.js

aihu output is standard ESM. Any Node.js ≥20.18.0 runtime can serve a aihu application:

```bash
npm run build
node dist/server/entry.js
```

The server entry is generated by the universal build and uses `@aihu/server`'s request router.

## Cloudflare Workers and Vercel Edge

aihu uses only Web Standard APIs (Fetch, ReadableStream, URL) in its server runtime, making it compatible with edge environments.

Set the `AIHU_NATIVE_SKIP` environment variable to disable any Node.js-specific compatibility shims:

```bash
AIHU_NATIVE_SKIP=1 bun run build
```

Deploy the `dist/server/` output as a Worker or Edge Function. The `@aihu/server` request router handles incoming `Request` objects and returns `Response` objects natively — no adapter layer needed.

## `defineAihuConfig`

The app configuration lives in `aihu.config.ts` (or exported from `vite.config.ts`):

```typescript
import { defineAihuConfig } from '@aihu/server'

export default defineAihuConfig({
  build: {
    target: 'universal',
    outDir: 'dist',
    sourcemap: false,
  },
  plugins: [],
})
```

## `@aihu/server` request router

The `createRequestRouter` handles edge function dispatch:

```typescript
import { createRequestRouter } from '@aihu/server'
import routes from 'virtual:aihu-routes'

const router = createRequestRouter({ routes })

export default {
  fetch(request: Request): Response | Promise<Response> {
    return router.handle(request)
  },
}
```

## `viteRouterIntegration()` at build time

The Vite plugin performs these steps at build time:

1. `scanPages(dir)` — discovers all `.aihu` files under `src/pages/`.
2. For each page, reads the `.route.json` sidecar emitted by the Rust compiler.
3. Assembles the route manifest into the `virtual:aihu-routes` module.
4. Emits `dist/routes.json` for runtime consumption.

This means route manifests are fully static after build — no filesystem scanning at runtime.

## Size budgets

The browser bundle has a hard ceiling at 3.46 kB gz. Every build validates against the size limits in `.size-limit.ts`. Exceeding the limit fails the build.

Run `bun run size` to check current bundle sizes without running a full build.
